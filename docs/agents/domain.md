# Domain documentation

This is a single-context repository.

## Before exploring

Read these resources when they exist and are relevant:

- `GLOSSARY.md` at the repository root.
- ADRs under `docs/adr/`.

If they do not exist, proceed silently. Domain-modeling work creates them lazily
when terminology or architectural decisions need to be recorded.

## Vocabulary

Use terms as defined in `GLOSSARY.md` in issue titles, proposals, hypotheses,
and test names. Avoid synonyms that the glossary explicitly rejects.

If a needed concept is absent, reconsider whether the project already has a
suitable term or record the gap for domain-modeling work.

## Architectural decisions

Surface any conflict with an existing ADR explicitly instead of silently
overriding the decision.
